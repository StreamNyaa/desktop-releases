# Feedback

Back up an existing installation first. For playback, use a small release you have permission to access. Do not download a large pack just to fill out this checklist.

## A short first test

1. Install using the [guide](install.md), open the app, and confirm version 0.1.15.
2. Browse Home, open a title, return, and try search. Check long titles and artwork.
3. Open Schedule. Change days, expand Details, and check that the time/status agrees with the track shown.
4. Bookmark a title, restart the app, and check that it remains in your library.
5. For permitted media, select the intended episode and use a source. Confirm that the chosen file is the correct installment and episode, and that video actually advances.
6. Pause, resume, seek, and switch subtitles/audio if available. Close playback and check that resume returns to that episode.
7. If you already have a permitted batch, check file selection and Next within it. One watched file must not mark the rest watched.
8. If an episode completes, check Replay, Close, and Next where a next episode exists.

Optional account testing: sign in, verify a bookmark on another device, and check that account switching does not mix libraries. Do not post account credentials or test another person's account.

## A good report includes

- StreamNyaa version and Windows version.
- CPU/GPU model if the issue concerns startup, decoding, or rendering.
- The title and exact episode/part. A provider title URL or ID helps distinguish seasons.
- A short sequence of steps, what you expected, and what actually happened.
- Whether it happens again after restarting, and whether another permitted source works.
- A screenshot or a small sanitized diagnostic excerpt, if needed.

For source problems, report the public release name and source provider. Avoid posting private tracker URLs, passkeys, personal paths, copyrighted media files, full backups, or entire log folders. Security problems belong in [private reporting](https://github.com/StreamNyaa/desktop-releases/security/advisories/new).

We may ask for one specific additional check. A reproducible report is more useful than running hundreds of requests or repeatedly retrying a provider that is already throttling you.
